# 自动化文件上传测试的工具选择与适配

- 来源：任务 #34 自动复盘（自我迭代）
- 保存时间：2026-11-19 12:39

**结论**：在自动化渗透测试中，当目标存在文件上传功能且需要构造 multipart/form-data 请求时，应优先使用支持文件上传的专用工具（如 curl、Python requests 库），而非通用 HTTP 请求工具（如 http_fetch），以避免因协议支持不足导致上传失败。

**适用场景**：任何需要上传文件（如 WebShell、图片马、恶意文档）的 Web 应用测试，尤其是目标使用标准 HTTP 文件上传表单且无特殊限制时。

**具体做法**：
1. 识别上传点：通过页面分析或抓包获取上传表单的 action URL、字段名（如 `file`）、以及可能的额外参数（如 CSRF token）。
2. 若自动化框架内置的 HTTP 工具（如 http_fetch）不支持 multipart 编码，则切换到外部命令执行工具（如 kali_exec）调用 curl：
   - 示例：`curl -X POST -F "file=@shell.php" -F "submit=Upload" -b "cookies.txt" "http://target/upload.php"`
   - 或使用 Python 脚本：`python3 -c "import requests; requests.post('http://target/upload.php', files={'file': open('shell.php','rb')}, cookies=cookies)"`
3. 若目标要求先获取 CSRF token，则先 GET 上传页面，解析 token 后与文件一起提交。
4. 验证上传结果：检查响应中是否包含“成功”字样或文件路径，并尝试访问上传的文件确认可执行。

**注意事项**：
- 注意文件大小限制、MIME 类型检查等服务器端过滤，必要时修改文件头或扩展名。
- 保持会话一致性：上传请求必须携带有效的认证 Cookie 和 CSRF token，否则可能被重定向到登录页。
- 对于高安全等级（如 DVWA Impossible），文件内容会被检查，需使用图片马或绕过内容检测。
